# TeleMotoMax Native для Motorola V8

Отдельный клиент на C++98 и Qt 2 для Motorola V8 с MotoMAGX/SAedition.
Java-клиенты V3, Light и V8 продолжают выпускаться отдельно; их версии,
установка и сохранённые данные не меняются. Нативный клиент подключается
к тому же мосту по OSCAR/TMM. Для Telegram, MAX и eXpress используются
существующие серверные учётные записи.

Версия нативного клиента: **0.1.20**. Совместимость с API оборудования
проверяется по библиотекам прошивки V8 SAedition 1BR. Запуск ARM-кода под
QEMU проверяет протокол, ABI и обработку данных, но не заменяет испытания
камеры, микрофона, звука, крышки и внешнего дисплея на телефоне.

Фотоальбом Telegram приходит одним сообщением с подписью. В чате и в истории
**Показать фото** открывает список снимков. Загрузка начинается после выбора.

## Установка

В GitHub Releases нативный клиент имеет отдельный тег
`telemotomax-native-v0.1.20`. Скачайте пакет из этого релиза и перенесите на
телефон по USB или Bluetooth. Скрипт обновления моста не скачивает нативные
пакеты; раздел `/d/` остаётся без изменений. Нативные пакеты не являются JAR/JAD.

* **TeleMotoMax-Native-V8.pep** — открыть через vInstaller SAedition.
  Устанавливается отдельный пункт **TeleMotoMax Native**.
* **TeleMotoMax-Native-V8.tar.gz** — распаковать каталог
  `TeleMotoMax-Native` в `/ezxlocal/download/mystuff/` и запустить
  `telemotomax.lin` штатным средством запуска `.lin` в прошивке.

Перед обновлением завершите нативный клиент через меню. В пакетах нет
изменений системных библиотек, прошивки или настроек Java. vInstaller
устанавливает приложение в `/ezxlocal/download/mystuff/TeleMotoMax-Native`.

В **Настройки → Учетная запись** введите UIN и пароль моста; в разделе
**Сеть** — адрес, порт и при необходимости PSK. Используются те же значения,
что в Java. Изменения раздела сначала сохраняются в форме: **Сохр.** применяет
их, **Назад** отменяет. Поддерживается одна учётная запись: только поля
UIN и пароль, без выбора, добавления и удаления других учёток. При обновлении
сохраняются данные текущей выбранной учётки; устаревшие дополнительные
UIN и пароли удаляются из файла настроек. Локальные данные текущего чата
при этом сохраняются.
Для мобильного Интернета выберите **Доступ в сеть → Мобильный профиль**
и **Профиль Интернета**. «Системный маршрут» использует уже поднятое
соединение; «Автоматически» без профиля также использует системный маршрут.
Пустой сервер, отсутствующий обязательный профиль или PSK показываются
как ошибка до запуска подключения. Этапы подключения и передача вложений
занимают весь экран. Во время подключения логотип и нижняя полоса
показывают этап и прогресс в одну строку. В центре используется значок
TeleMotoMax; клавиши **Назад**, **Отмена** и очистки прерывают
подключение, хотя подпись отмены на экране скрыта, как в Java.

При включённой настройке **Сеть → Поддерживать подключение?** первый пинг
уходит сразу после входа, следующие — с выбранным интервалом. Каждый
отправленный пинг получает полный интервал на ответ. Входящие данные
сбрасывают счётчик и во время загрузки вложения. Интервал и порог
**Пингов без ответа** применяются при сохранении настроек. На V8 сетевой
поток ставит таймер Motorola `/dev/rtc_sw` на тот же интервал. Если прошивка
закрывает к нему доступ, поток проверяет прошедшее время по двум часам,
в том числе сразу после пробуждения. В `launcher.log` строка
`OSCAR keepalive #N sent` означает, что клиент записал пинг в сокет.
В журнале моста на уровне INFO «пинг от телефона» подтверждает его получение.

## Меню и действия

Меню и переходы основаны на Java V8 1.32
(`MOTOROLA`, `CAMERA`, `AVATARS`, `MOTOMAGX`). Списки, формы, заголовок и
софт-клавиши оформляет системная тема Motorola, как в моде «Переписки»
для SMS. Контекстное меню чата открывается поверх переписки; нижний пункт
**Ответ...** выбран сразу. Отдельного экрана команд сообщения нет.

* **Меню:** подключение/отключение, статус, контакты, чаты, настройки,
  включение/выключение звука, о программе, свернуть и выход.
* **Контакты:** все чаты, добавление и поиск контакта, создание, удаление
  и переименование групп, приватные списки. **Меню контакта** содержит
  информацию, действия с контактом и списками в зависимости от подключения.
* **Меню чата:** история с сервера, получение без оповещений, копирование,
  цитирование и действия с выбранным вложением, а также съёмка, запись и
  отправка файлов. Доступные команды зависят от выбранного сообщения.
* **Настройки:** учетная запись, сеть, интерфейс, камера, медиа,
  Telegram, MAX, eXpress, горячие клавиши,
  оповещения, часовой пояс, шаблоны и сброс настроек.

Внутри каждой группы чаты с непрочитанными сообщениями находятся сверху.
Список чатов использует тот же системный список Motorola, что и меню:
выделение, фон, шрифты и прокрутка оформляются темой телефона. Ромашки
статусов, конверты непрочитанного, счётчики и вложенные группы сохраняются.
В обеих частях списка сохраняется выбранная сортировка по статусу или имени.
Порядок перенесён из Java: имена сравниваются без учёта регистра, в том числе
кириллица; сортировка по статусу различает онлайн, свободен для общения,
отошёл, занят и другие статусы, а не только онлайн/офлайн. При одинаковом
статусе учитывается имя, равные ключи сохраняют входной порядок контакт-листа.
После прочтения чат возвращается на обычное место. Это действует и для тихих
сообщений, и при выключенных группах; курсор сохраняется на выбранном контакте.

Запуск, сохранение настроек и возврат из фона используют один режим окна.
При выключенном **Полный экран** приложение разворачивается на всю доступную
рабочую область, при включённом — открывается полноэкранно. Сохранение
любого раздела сохраняет развёрнутый размер, без возврата к маленькому окну.

В списке контактов софт-клавиши — **Меню / Выбрать**, в чате —
**Закрыть / Меню**. **Ответ...** открывает редактор; выбор сообщения с видео —
подменю просмотра. Заголовок чата показывает
имя и, если открыто несколько чатов, его номер среди открытых чатов.
Сообщения оформлены по принципу Java: имя и время — отдельный полужирный
заголовок, красный для входящих и синий для исходящих. На тёмном фоне
используются светлые оттенки этих цветов; основной текст сохраняет
цвет системной темы. Работают настройки имени, времени, даты и переноса после
заголовка. Выделение сообщения — мягкое серое, с оттенком для светлого или
тёмного фона; основной текст остаётся в цвете темы. Даты и отправители из
истории сервера выделяются без повторного имени чата и выдуманной даты
1970 года. Стрелка или отметка доставки занимает место только на первой
строке сообщения. Текст под ником и перенесённые строки начинаются у левого
края стрелки. Длинные слова и адреса переносятся.

Пустой чат показывает **Загрузка…**, пока выполняется запрос последнего
сообщения, истории или восстановления чата; после пустого ответа —
**Сообщений нет**. Ошибка и отключение завершают состояние загрузки.
Служебные сообщения, например **Загружаю историю…**, выводятся в самой
верхней строке вместо заголовка. Нижнего баннера и отступа под него нет;
после окончания уведомления возвращается обычный заголовок. При вводе на
полном экране служебная строка временно занимает место сверху, сохраняя текст.

Фон нижней строки софт-клавиш берётся из настоящего элемента `ZSoftKey`
выбранной системной темы, вместе с её прозрачностью и геометрией. Он
собирается на сплошном фоне темы, поэтому сообщения и фотографии под ним
не просвечивают. Результат кэшируется до смены темы или размера окна.

В **Интерфейс → Значок запущенного приложения** доступны **Строка статуса**
(по умолчанию), **Экран ожидания** и **Нет**. Значок остаётся при сворачивании;
обычный выход удаляет его. При соединении видна ICQ-ромашка. После установки
дополнения темы отсутствие связи, подключение и переподключение показываются
той же ромашкой в оттенках серого; непрочитанные добавляют конверт к текущему
значку, в том числе серому. Статусы отсутствия, занятости и невидимости
сохраняются. **Сохр.** меняет размещение
сразу, **Назад** отменяет. Штатный слот верхней строки общий с Bluetooth/USB:
значок может скрывать их индикацию. **Экран ожидания** использует другой
слот. Повторные обновления интерфейса с тем же статусом и признаком
непрочитанного не отправляют сообщения панели. Конверт учитывает тихие
сообщения и снимается после прочтения всех чатов. Число непрочитанных
остаётся в заголовке и контакт-листе клиента.

### Дополнение темы: серая ромашка и конверт

После установки 0.1.16 или новее завершите клиент через **Выход**. В его каталоге
`/ezxlocal/download/mystuff/TeleMotoMax-Native/` запустите
**install-status-icons.lin**, дождитесь сообщения об установке и
**перезагрузите телефон**. Затем запустите клиент. В настройке значка
должна быть выбрана строка статуса либо экран ожидания.

Установщик создаёт копию выбранной темы в
`/ezxlocal/download/appwrite/TeleMotoMaxStatusIcons/skin`, добавляет в её
`iconres.ezx` только ресурсы `tmm_*` и меняет `CurrentSkin` в
`/ezxlocal/download/appwrite/setup/ezx_theme.cfg`. Прочие файлы оформления
остаются ссылками на исходную тему; её изображения и системный общий пакет
не перезаписываются. Конфигурация до установки сохраняется рядом с копией
темы в `theme-backup.cfg`, исходный путь — в `source-skin`.

Откат: завершите клиент, запустите **restore-status-icons.lin**, затем
перезагрузите телефон. Восстанавливается только выбор темы, другие текущие
настройки сохраняются. Если после установки вы выбрали другую тему,
скрипт отката её не заменит. Для новой темы повторите установку дополнения
и перезагрузку. Обновление самого клиента переустанавливать дополнение не
требует. До установки или после отката клиент использует прежние штатные
значки без конверта.

Для повторного создания небольшого пакета изображений разработчик может
запустить `python3 native-v8/tools/make_status_icons.py` с Pillow.
Исходные ICQ-значки экспортированы штатным загрузчиком прошивки V8;
полные пакеты изображений прошивки в дистрибутив не включаются.

### Список чатов
Группы при входе свёрнуты; обновление статусов сохраняет ручное раскрытие.
Непрочитанные сообщения показываются конвертом и числом у чата и всех
родительских групп, даже свёрнутых; общий счётчик виден в заголовке.
После просмотра чата, возвращения из фона или снятия блокировки его значок
сбрасывается. Статусы прочитанных чатов используют ромашки из Java V8; «невидимый» означает недоступную сеть
и не включается в число онлайн. Цвета собственных экранов берутся из системной
палитры Motorola. Цветовые схемы и фоновое изображение удалены, включая
старые значения настроек и лишний `back.png` в пакете.
В **Интерфейс** отдельно выбираются **Размер шрифта** и
**Размер шрифта в чате**: 12, 14, 16, 18, 20, 22 или 24 пункта. Старые
флажки мелкого шрифта переносятся в размеры; явно заданные размеры сохраняются.

**История с сервера** добавляет сообщения прямо в переписку в порядке
от старых к новым. Общие идентификаторы сообщений устраняют повторы,
сохраняются квитанции, части длинного сообщения и позиция чтения.
**Ещё с сервера** в меню чата загружает предыдущую страницу. Одновременно
выполняется один запрос истории данного чата; запрос во время подгрузки
последнего сообщения ждёт её завершения. Ошибка показывается в чате,
после неё запрос можно повторить. В памяти хранится до 200 сообщений
загруженной переписки; страницы не перезаписывают локальный архив.
Обсуждения остаются своим списком сообщений. Отдельных пунктов локальной
истории и поиска по ней нет, как в используемой Java-сборке V8.

**Настройки → Интерфейс → Сохранять локальную историю** управляет архивом
на телефоне; по умолчанию сохранение включено. **Сохр.** с выключенным
флажком удаляет локальную историю, включая архивы прежних учётных записей и прекращает её
чтение и запись, включая обновление квитанций на диске. **Назад** отменяет
изменение. Текущая переписка и квитанции продолжают работать в памяти до
выхода; черновики, контакты и шаблоны сохраняются отдельно.

После перезапуска пустой чат запрашивает ровно одну последнюю запись
истории у моста, как Java. Это работает и для чата, открытого до подключения;
повторное открытие не дублирует уже идущий запрос. Подгрузка не создаёт
непрочитанное сообщение и не подменяет уже пришедший новый текст. История
с сервера использует готовые дату и автора в ответе моста: лишние
`01.01 03:00` и имя чата перед ними не добавляются.

**Получать без оповещений** сохраняет выбор на клиенте и передаёт его мосту.
Заглушённый чат продолжает получать сообщения и значок непрочитанного;
для этих сообщений нет звука, вибрации и пробуждения экрана. Обычные
сообщения используют мелодию, громкость и вибрацию из **Оповещения**:
отдельно для открытого приложения и блокировки/закрытой крышки. Первые
60 секунд после запуска звук и вибрация подавлены; значки появляются сразу.
Режим **Откл. звук** в главном меню также сохраняется между запусками.

Список смайлов содержит все 32 изображения и кода из Java SMILES_STD;
выбранный код вставляется с пробелами. Единственная найденная ссылка
открывается сразу, несколько ссылок дают список выбора.

Для уведомлений используется штатный короткий сигнал Motorola; новое
оповещение не перезапускает ещё звучащее. При просмотре или записи медиа
уведомления сохраняют непрочитанное и вибрацию, уступая звуковое устройство
плееру/микрофону. Перед съёмкой, записью и воспроизведением текущий сигнал
останавливается. Ошибка `Motorola: 7` означает занятое звуковое устройство;
после ошибки плеер освобождается и следующее оповещение может повторить запуск.
В 0.1.7 запуск повторяет штатный порядок V8: открытие файла, выбранная
громкость, воспроизведение. Убраны лишнее закрытие устройства перед запуском
и снятие mute с восстановлением максимальной громкости. Уже полученное
завершение не заменяется поздней ошибкой; настоящие ошибки до завершения
показываются с кодом из события плеера.

В 0.1.9 исправлены сами короткие MP3: reader этой прошивки требует полный
начальный блок 4096 байт после ID3v2. Меньший файл получает Motorola: 2 ещё
при разборе. Для native подготовлены отдельные `message.mp3`, `msg_low.mp3`
и `typing.mp3` (22 050 Гц, CBR 96 кбит/с, прежнее число каналов, без тегов).
Они проверены настоящим reader из прошивки. Работающий `tg.mp3` используется
в исходном виде. Имена в настройках сохраняются; при обновлении устанавливайте
пакет целиком вместе со звуками.

Исходники Java используют свои прежние ресурсы. Native-файлы уже включены
в репозиторий: ffmpeg для обычной сборки или установки не требуется.
Для их повторной подготовки разработчик может запустить
`python3 native-v8/tools/prepare_sounds.py --ffmpeg /путь/к/ffmpeg`
со сборкой, содержащей libmp3lame. Громкость `msg_low` сохраняет ослабление
исходного файла; дополнительное усиление при подготовке не применяется.

## Медиа

С 0.1.19 native запрашивает MPEG-4 SP в 3GP, чтобы выбранные размеры кадра
(например, 240×180) и поворот на 90° не ограничивались стандартными кадрами
H.263. Для этого нужно обновить и мост: параметр кодека передаётся отдельной
необязательной парой 21 в настройках «Медиа». Java и классические клиенты
продолжают использовать кодек из конфигурации моста.

«Ролик боком»: **авто** поворачивает широкие исходники, **всегда** — любой,
**никогда** — отключает этот поворот. Поворот, заданный метаданными исходника,
учитывается перед выбором. При повороте ширина и высота кадра меняются местами.
Мост вписывает картинку с сохранением пропорций и добавляет чёрные поля;
параметры кадра задают размер всего выходного кадра, а не растягивание картинки.

В «Медиа» можно выбрать длину до **60 минут**, битрейт до **1024 кбит/с**
и размер до **512 МиБ**. Явный выбор «Видео: не больше» задаёт отдельный
предел видео; «по лимиту загрузки» использует общий лимит вложений (8 МиБ
по умолчанию). При маленьком пределе мост снижает битрейт. Для часа при
192 кбит/с подойдёт 128 МиБ, при 1024 кбит/с — 512 МиБ.

Для больших файлов native согласует дополнительные пары 22 (предел в МиБ)
и 23 (номера частей BART по 16 бит): прежний формат ограничен 255 частями.
Маленькие ответы сохраняют прежний формат; Java и Jimm его не меняют.
Видео пишется на диск частями, а дисковый кеш при явном выборе большого
предела расширяется до него, максимум 512 МиБ. Это не выделение оперативной
памяти под весь ролик. На подготовку длинной части мосту отводится до двух
её длительностей. Исходный файл всё ещё ограничен `[render] source_max_mb`
на сервере; для большого оригинала этот параметр нужно увеличить.

Повышенные битрейты и VGA кодируются с MPEG-4 SP Level 4a. Воспроизведение
этих вариантов на конкретной прошивке V8 проверяется на телефоне.

В меню чата находятся прямые команды **Снять фото**, **Записать голосовое**,
**Записать кружок**, **Отправить файл**, **Отправить фото/видео**. Отдельного
меню «Прикрепить» и подтверждения с предпросмотром перед отправкой нет.

В 0.1.11 исправлена потеря сигнала готового медиа: после закрытия камеры
результат съёмки передаётся в отправку. Исправление также относится к
завершению записи голосового.

В камере **выбор / 5** снимает фото либо запускает и останавливает кружок.
Правая **Останов.** во время записи также завершает и отправляет кружок;
до начала записи правая клавиша отменяет камеру.
Готовые данные сохраняются из нативного буфера до уничтожения диалога камеры,
затем передаются мосту. Режим фото может вообще не создавать отдельного
файла: `GetCameraData` возвращает его содержимое в памяти. Автоматическая
вставка фото вызывает штатное действие камеры с проверкой размера;
вручную нажимать «Вставка» не нужно. Адаптер учитывает и экраны
нативных frames, не являющиеся дочерними окнами диалога.
Штатный видоискатель Motorola сохраняет оформление телефона. Голосовое
сначала открывает экран ожидания: **выбор / 5** начинает запись, повторное
нажатие показывает «Сохраняю запись...» и отправляет готовое голосовое.
**Назад** отменяет и во время остановки. Микрофон открывает и закрывает
только рабочий поток; уведомления во время записи не запускают второй плеер. Максимум
голосового — 60 секунд, кружка — 30 секунд.

Обе команды отправки из памяти сразу открывают **Root** с доступными
корнями, папками и **../**. Доступны `mystuff`, `/ezxlocal`, карта памяти
(если доступны для чтения) и всегда `/` для прочих путей. Корни подписаны
полным путём. Выбор файла начинает отправку. **Отправить файл**
сохраняет вид документа; **Отправить фото/видео** распознаёт JPEG/PNG/GIF/BMP и
3GP/MP4/3G2/AVI/MOV по расширению, остальные файлы отправляет документами.
Видео из памяти отправляется обычным видео, запись камеры — кружком.
После передачи байтов клиент ждёт ACK моста. При ошибке временная запись
остаётся доступной для повтора; успешный ACK или отмена удаляет только
принадлежащий клиенту временный файл, сохраняя выбранный оригинал.

**Смотреть видео** открывает подменю **Смотреть / Смотреть в браузере**,
если у сообщения доступны оба способа. Встроенный видеоплеер занимает всю
рабочую область: **выбор / 5 / 0 / Назад** закрывает, **3 / Дальше** запрашивает
следующий фрагмент. Голосовой плеер показывает время и полосу: **выбор / 5**
ставит на паузу, продолжает или повторяет завершённое; **влево / 4** начинает
сначала, **0 / Назад** закрывает.

Аватары и полученные фото открываются общим просмотрщиком: вверх/вниз
меняют масштаб, влево/вправо поворачивают, **выбор / 5 / 0 / Назад** закрывает.
Текстовая подсказка поверх фотографии удалена; изображение занимает всю
область между системными полосами.
**Скачать файл** автоматически сохраняет документ в `tmm/` на доступном
корне памяти, затем показывает путь и размер. Совпавшее имя получает
суффикс, существующий файл не перезаписывается. Полученное в фоне вложение
открывается после возврата, открытия крышки и разблокировки; скрытый клиент
не запускает воспроизведение.

## Отличия от Java и проверка на телефоне

* Нативному приложению нужен выбор профиля Интернета Motorola: в Java это
  выполняет виртуальная машина. Сетевые операции всегда работают в отдельном
  потоке, поэтому флажка «Асинхронная передача» в меню нет.
* Мост не передаёт программу собеседника; **Инфо о клиенте** сообщает об этом.
  Корни файловой системы показывают реальные имена MotoMAGX, которые могут
  отличаться от псевдонимов JSR-75 в Java.
* Масштаб/поворот фото и **Показать пароль / Скрыть пароль** оставлены
  по прежним отдельным запросам. Настройки цветов и фона удаляются при
  обновлении; остальные данные сохраняются.
* Адаптер камеры проверяет ABI целевой прошивки. Проверки кода и библиотек
  не заменяют съёмку, воспроизведение, звук, крышку и возврат из фона на V8;
  порядок проверки приведён в [VALIDATION.md](VALIDATION.md).

Повторный запуск активирует уже работающий клиент, включает подсветку и
восстанавливает фокус. Индикаторы режима, регистра и языка над редактором
приходят от движка Motorola; Input Cycle управляет языками по `#`, как в
штатном редакторе. Клиент не меняет библиотеки и список языков прошивки.
Пароль использует режим без словаря и автоматической заглавной буквы.
При сворачивании, закрытии крышки или блокировке показанный пароль снова
скрывается. Пароль учётной записи кодируется в Latin-1, как ожидает мост;
неподдерживаемые символы дают ошибку до подключения. PSK использует UTF-8.

Если приложение закрылось с ошибкой, запустите **collect-log.lin** из каталога
установки или скопируйте этот скрипт в удобный каталог и запустите там.
Рядом появится **TeleMotoMax-log.txt** с `launcher.log` и
`launcher.previous.log` — журналами текущего и предыдущего запусков.
Для **Windows XP** в пакете есть `collect-log-xp.cmd`. Сначала создайте отчёт
скриптом `collect-log.lin` на телефоне, затем подключите V8 в режиме USB-памяти
и запустите CMD на компьютере. Он ищет готовый отчёт на подключённых дисках
и копирует его в `%USERPROFILE%\TeleMotoMax-logs\TeleMotoMax-log-N.txt`,
сохраняя прежние отчёты. Если каталог установки нестандартный, перетащите
его из Проводника на CMD либо передайте путь первым аргументом.
PowerShell, Python и дополнительные программы не требуются.
Скрипт не копирует настройки и историю чатов. С 0.1.2 запуск записывает
только stderr: отладочный stdout штатного движка Motorola содержит вводимый
текст, в том числе пароль, и теперь отбрасывается. Старые журналы 0.1.1 могут
содержать этот текст, в том числе в `launcher.previous.log`; проверьте их
перед пересылкой. При отсутствии журнала это будет явно указано в отчёте.

## Данные и ресурсы

Настройки и данные сохраняются отдельно от установленной программы:
`/ezxlocal/download/appwrite/TeleMotoMaxNative`. Адрес можно переопределить
переменной `TMM_NATIVE_DATA` при ручном запуске. Секреты не включаются в
архивы приложения или журнал. В личном каталоге они хранятся локально;
PIN блокирует интерфейс и не шифрует файлы на диске.

История, черновики, шаблоны, контакт-лист и тихие чаты разделены по
адресу моста, порту и UIN. Выбранный DNS IP не меняет эту привязку.
Обновление пакета сохраняет каталог данных. Перенос Java RMS не выполняется:
для нового клиента один раз задаются настройки заново.

Файлы записываются через временный файл и переименование. Локальная история
имеет ограничение числа сообщений и 2 МиБ на чат; большие вложения хранятся
отдельно, а не внутри истории. Повреждённая история не заменяется молча.
Сетевые операции выполняются в отдельном потоке с ограниченными очередями;
интерфейс получает события через дескриптор, без опроса сети в отрисовке.

Полный перечень переносимых возможностей находится в `features.tsv`.
Он сопоставляет функции Java и нативной версии и отмечает проверку каждого
пункта. Оборудование, которое нельзя воспроизвести в QEMU, отмечается отдельно.

## Сборка

Нужен MotoMAGX SDK с заголовками V8, GCC 3.4.3 и Qt 2 moc. Версия SDK
зафиксирована коммитом и SHA-256 в `tools/fetch_sdk.py`:

```sh
python3 native-v8/tools/fetch_sdk.py --output /tmp/tmm-sdk
python3 native-v8/tools/prepare_qemu_sdk.py \
  --sdk /tmp/tmm-sdk --qemu /usr/bin/qemu-i386-static --output /tmp/tmm-compiler
make -C native-v8 SDK=/tmp/tmm-sdk \
  CXX=/tmp/tmm-compiler/arm-linux-gnueabi-g++ \
  MOC=/tmp/tmm-compiler/moc -j2 package core-tests
```

Нужны Python 3.12+ для безопасной распаковки SDK, `make` и QEMU user static.
На Ubuntu x86_64 установите `qemu-user-static libc6-i386 lib32stdc++6`:
QEMU не содержит загрузчик и системные библиотеки i386 для компилятора SDK.
Компилятор SDK — i386; обёртки QEMU позволяют использовать его на x86_64
без изменения системного `binfmt`. Qt и библиотеки Motorola берутся с телефона,
не включаются в пакет и не заменяются установщиком.

```sh
python3 native-v8/tests/test_crypto.py
python3 tests/test_native_release.py
```

Для криптотестов нужен Python `cryptography`. Они сравнивают результат C++
с протоколом моста, включая проверку повреждения и повтора пакетов.
`TMM_CRYPTO_DRIVER` позволяет выполнить те же тесты с ARM-бинарником под QEMU.
Сборка и публикация выполняются отдельным workflow `native-v8-release.yml`.
Релиз неизменяемый: изменение исходников пакета требует новой native VERSION.
Java VERSION увеличивать для нативных изменений не требуется.

Лицензия — GPL, см. `COPYING` в пакете. Ресурсы и протокол совместимы
с TeleMotoMax/Jimm; адаптеры Motorola основаны на доступном SDK и проверке
библиотек текущей прошивки. Исходники SDK: fillsa/motomagx-SDK-toolchain,
коммит `eadb88fdd471c5013b538166b692a0ddad9e5774`.

## Просмотр фото и видео

Уже открытые фото и фрагменты видео повторно берутся из дискового кэша:
до 8 файлов общим объёмом до 16 МиБ. Старые файлы вытесняются по последнему
использованию. В куче хранятся только сведения о файлах; изображения после
закрытия просмотрщика освобождаются. Размер, качество и поворот входят
в ключ кэша; каждый фрагмент видео хранится отдельно. Удалённый с диска файл
клиент скачает заново. Кэш очищается при выходе, смене учётной записи, а после
аварийного завершения — при следующем запуске.

Служебный URL видеосообщения скрыт в переписке. Подпись, длительность и
пометка `[видео]` остаются; адрес доступен через меню просмотра в браузере.
В меню статусов используются те же ромашки, что в Java. Экран блокировки
показывает дату, день недели, число непрочитанных и состояние подключения,
не раскрывая содержимое чата. При установленном PIN ввод начинается сразу:
`*` или очистка стирают цифру, софт-клавиши очищают ввод. Без PIN разблокировка
остаётся на `#`.

Значок заставки 96×96 собирается из исходного рисунка TeleMotoMax командой
`python3 native-v8/tools/make_logo.py` из корня репозитория (Pillow). Обычная
сборка использует готовый PNG. Подписи этапов подключения сокращены; при
большом шрифте строка завершается многоточием и не переносится.
