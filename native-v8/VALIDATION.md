# Проверка TeleMotoMax Native 0.1.12

Целевая платформа — Motorola V8, MotoMAGX/SAedition 1BR, ARM EABI,
Qt Embedded 2 и библиотеки Motorola из прошивки. Поведение меню сверяется
с Java V8 1.31: `MOTOROLA`, `CAMERA`, `AVATARS`, `MOTOMAGX`, без модулей
`HISTORY`, `PIM`, `TRAFFIC`. Java, протокол и конфигурация моста не меняются.
Нативные пакеты распространяются через GitHub Releases, без `/d/`.

## Системный список чатов в 0.1.12

Контакт-лист отображает тот же ZListBox с теми же регионами шрифта,
выделением и фоном, что и меню. Группы и счётчики остаются в View;
клавиши сохраняют прежние действия и границы списка. Конверт непрочитанного
и ромашки статусов передаются в native items из прежних PNG-атласов.

Native-объектов по-прежнему не больше 32. Изменения статуса, счётчика или
порядка обновляют содержимое имеющихся строк; смена страницы, размера
шрифта или числа строк пересобирает страницу. Состояние иконки включено
в подпись кеша, поэтому статус обновляется и без изменения имени.
Общие 16×16 значки создаются по мере использования и повторно используются.

UI-проба проверяет настоящий ZListBox, состав иконок через штатный getter,
сохранение выбранного контакта при обновлении статуса, повторное использование
строк и границы навигации. Прежняя ручная отрисовка контакт-листа удалена.
`native-0112-roster-theme-a2` проходит 153 проверки, в том числе значки,
повторное использование native items и вложенные группы; итоговый снимок
проверен визуально. `native-0112-menu-regression-a1` проходит 172 проверки
меню, действий и софт-клавиш. Шестипараметровый setter строки вызывается по
реальному экспорту V8/SDK: объявленный SDK дополнительный ShowPriority
отсутствует в библиотеке; при обновлении сохраняется приоритет из append.

## Сигнал готового медиа и QObject SDK в 0.1.11

В SDK перед `QObject::blockSig` отсутствует один бит. Его inline
`signalsBlocked()` читает бит 4 первого слова флагов, а настоящий
`QObject::blockSignals(bool)` V8 (`0x415433b4`) записывает бит 5 по смещению +4.
У контроллера камеры с родителем старый getter возвращает true даже после
штатного `blockSignals(false)`. Сгенерированный moc для двух аргументов
вызывает этот getter и отбрасывает `ready(path, mime)`: после «Вставка»
диалог закрывается, но команда отправки не создаётся. Прежняя проверка с
прямым вызовом `Window::captureReady` обходила дефект.

`tools/prepare_qt_compat.py` формирует копию qobject.h с недостающим битом
в build/qt-compat. Она предварительно включается во все ARM translation units;
внешний SDK остаётся прежним. Размер QObject остаётся 36 байт, смещения
его указателей и размер контроллеров не меняются. Дополнительной памяти
или опроса в работающем приложении нет.

`qt_object_test.cpp` сверяет inline getter с настоящими конструктором и
blockSignals() для родителя и ребёнка. `capture_lifecycle_test.cpp` теперь
создаёт контроллер с родителем. `media_workflow_probe.cpp` доставляет фото
и кружок через настоящий Qt-сигнал готовности и проверяет тип команды,
получателя, подтверждение и удаление временного файла. Физическая съёмка
этими проверками не подменяется.

Старый заголовок воспроизводит ошибку на родительском QObject (assert,
SIGABRT); совместимая копия проходит ту же проверку с настоящим Qt V8.
Старые сборки `native-0110-camera-signal-a1/a2/a3` не создают команду после
настоящего ready-сигнала; штатный blockSignals(false) ошибочный getter не
исправляет. После исправления `native-0111-media-signals-a1` проходит
78 проверок, `native-0111-unread-ui-a1` — 137, `native-0111-camera-ui-a1`
подтверждает маршрутизацию Вставка/Стоп и завершение native-диалога.
Полный firmware-check и 16 тестов упаковки проходят.

## Непрочитанные чаты в 0.1.10

В каждой группе сначала выводятся непрочитанные чаты, затем прочитанные;
в обеих частях сохраняется текущая сортировка по статусу или имени.
Два прохода по уже отсортированным индексам не создают вторую копию списка.
Выбор режима сортировки читается один раз при перестроении контакт-листа.

`ui_probe.cpp` проверяет настоящий `Window` на Qt/QWS прошивки: тихое
входящее поднимает офлайн-чат выше прочитанного онлайн-чата, выбранный контакт
сохраняется, приоритет действует при сортировке по имени и без групп.
Проверяются скрытие офлайн после прочтения, обычный порядок после чтения
и порядок внутри нескольких непрочитанных чатов.
Запуск `native-0110-unread-sort-a2` завершился с кодом 0: 137 проверок UI,
из них 10 проверяют приоритет непрочитанных и возврат обычного порядка.

## Короткие MP3 и Motorola: 2 в 0.1.9

Наблюдение «работают Сигнал и tg.mp3» воспроизведено настоящим
`libezx_mpsdk_ringtone.so`. Его MP3 init (`0x41e2bcd0`) пропускает ID3v2,
затем сравнивает результат чтения с 4096 (`0x41e2be14`). Короткое чтение
или ошибка ввода ведут к возврату 2 (`0x41e2bf24`). Размер файла с тегами
не равен длине доступного начального блока аудио: у typing.mp3 тег 1024 байта.

| Файл | Исходный размер | Размер native | Native Open, исходный → новый |
|---|---:|---:|---|
| message.mp3 | 2194 | 7210 | 2 → 0 |
| msg_low.mp3 | 2403 | 7837 | 2 → 0 |
| typing.mp3 | 4287 | 5329 | 2 → 0 |
| tg.mp3 | 5747 | 5747 | 0 → 0 |

Три native-ресурса перекодированы libmp3lame в CBR 96 кбит/с без ID3/Xing;
частота и число каналов сохранены. Данные Java остаются прежними, tg.mp3
пакуется из прежнего общего ресурса. Генератор `tools/prepare_sounds.py`
сохраняет отдельные native-файлы, поэтому ffmpeg не становится зависимостью
обычной сборки. Файлы включены в fingerprint релиза и проверку точных байтов
обоих пакетов. Проверка размера при упаковке учитывает пропущенный ID3v2.

`notification_format_test.cpp` создаёт настоящий ringtone reader, открывает
все четыре упаковываемых MP3 и три исходных коротких файла. Для открытых MP3
тот же декодер синхронно вызывается до нормального EOF (4): проверяются PCM,
завершение и отсутствие обращений к выходу при декодировании. Только интерфейсы
выхода/уведомлений заменены инертными функциями. Подтверждены 0 для новых
ресурсов и 2 для коротких исходников до вызовов выходного интерфейса.
Play, AAL и динамик не запускаются. Воспроизведение через физический динамик
остаётся проверкой на телефоне. Весь firmware-check и 16 тестов упаковки
включают эти проверки и исходный случай typing.mp3 размером больше 4096.

## Получение результата камеры в 0.1.8

`CAM_UI_Dlg::done` в прошивке (`0x42e52954`) для режима фото 1 забирает
QByteArray из PhotoInsertView в поле диалога +384. Для режима видео 2 он
также заполняет этот буфер содержимым готового видео. `GetCameraData`
возвращает `const QByteArray&` через `CAM_UI_Dlg::data` (`0x42e51d04`),
а `GetCameraFileName` возвращает другую строку модели (+584).
SetCameraFileName задаёт запрошенное имя (+588), а не гарантирует файл
в результате. Прежняя попытка читать только имя теряла фото из буфера.

Клиент пишет готовые байты в собственный staging-файл до DestroyCameraDlg,
без второй копии буфера в памяти. При пустом буфере остаётся путь получения
готового файла. Проверяются лимит 4 МБ и ошибка записи. После сохранения
диалог отключается от адаптера и уничтожается; фотография проверяется и
при необходимости уменьшается, затем результат передаётся в отправку.
Фазы возврата, сохранения и уничтожения камеры записываются в launcher.log.

Для PhotoInsertView используется настоящий `insertSlot` (`0x42e33654`),
который проверяет размер и выполняет штатное завершение view перед done
менеджера. Адаптер не читает указатель кадра для посторонних Qt-событий
и после начала завершения. `camera_ui_v8_test.cpp` проверяет этот путь,
включая недоступный указатель кадра во время перехода. `camera_filename_test`
исполняет настоящие экспорты прошивки на защищённых буферах: фото без имени,
сохранение до очистки, fallback на файл и ошибку записи. Аппаратная съёмка
и наблюдаемый вылет требуют повторной проверки на телефоне.

`collect-log-xp.cmd` работает с готовым отчётом из USB-памяти. Это ASCII CMD
с CRLF и командами Windows XP; файлы отчётов копируются под новыми именами
в каталог профиля Windows. Упаковка и fingerprint включают скрипт. Запуск
на настоящей Windows XP не эмулируется Linux-проверками.

## Завершение и запуск звука в 0.1.7

Порядок запуска сверён со штатным `libezxvoicenote.so.1.0.0`:
`CreateRingtoneEngine` (`0x427e2770`) создаёт обычное аудиоустройство и
передаёт его фабрике, `PlaySoftTone` (`0x427e29d8`) вызывает open,
setVolume, play. Между конструктором и фабрикой нет flush/close, явного
unmute перед play тоже нет. Конструктор устройства уже вызывает AAL_open
(`libezxsound.so`, `0x41b7a66c`, init `0x41b7a428`); прежние flush/close
добавляли цикл закрытия/открытия. Явный unmute (`0x41f8ebf4`) сначала
восстанавливал исходный уровень 7, до установки пользовательской громкости.
Оба лишних действия удалены. Это устраняет лишние операции аудиотракта;
исчезновение слышимого щелчка проверяется на физическом V8.

В адаптере сохраняется первое завершающее событие: после playFinished
поздние error/unavailable/position и готовый startup timeout не подменяют
его. Ошибка до завершения сохраняется, в том числе с кодом 2 или 7.
Код берётся из аргумента настоящего сигнала `errorOccurred(MPError)`;
экспорт прошивки `errorOccurred(unsigned short)` подтверждает его тип.
getError используется только при неудаче синхронного open/play без сигнала.
Удаление плеера отложено до возврата нативного callback, состояние
сбрасывается до деструктора. После завершения таймер запуска не включается снова.

`media_start_test.cpp` исполняет производственный play/stop и Qt-переходы
с библиотеками прошивки. Подменены только фабрики/медиа-вызовы и аппаратное
устройство. Проверяются порядок open → volume → play без flush/close/unmute,
finish → error и error → finish, ошибка при volume без последующего play,
синхронный отказ, код из сигнала при отличающемся getError, отмена ожидающего
события, повторный запуск и освобождение до уведомления GUI. Отдельно
проверены ringtone и обычный плеер. Декодер и динамик не запускаются.
При контрольном возврате каждой из трёх прежних ошибок (лишнее закрытие,
подмена завершения ошибкой, чтение устаревшего getError) тест падает на
соответствующей проверке. Исправленный вариант проходит весь firmware-check.

## Поведение 0.1.6

Меню и формы сохраняют оформление Motorola. Состав, порядок, доступность
команд и софт-клавиши перенесены из `MainMenu`, `ContactList`, `JimmUI`,
`ChatHistory`, `HistoryViewer` и `Options`. В чате используется одно
контекстное меню поверх переписки; команды следуют сортировке приоритетов
Java, по умолчанию выбран нижний ответ. Отдельного меню сообщения на выбор
нет. Контакты, группы, приватные списки, авторизация, шаблоны, информация
и подтверждения удаления используют соответствующие действия Java.

Редактор имеет **Отмена / Меню**, отправку/ОК и вставки из его меню.
Настройки раздела редактируются в черновике: **Сохр.** применяет изменения,
**Назад** отменяет, ошибка проверки оставляет форму открытой. Единственная
учётная запись содержит UIN и пароль и также сохраняется правой кнопкой.
Списки выбора, флажки, секции
интерфейса, сети, медиа, оповещений и часового пояса повторяют Java.
Все экраны используют палитру и оформление системной темы Motorola.
Отдельные схемы, фон, старые настройки и back.png удалены. Размеры шрифтов
интерфейса/редактора и чата выбираются отдельно (12/14/16/18/20/22/24).
Проверяются миграция старых флажков, сохранение явных размеров, Save/Back,
применение к настоящим Window, ZMultiLineEdit и нативным спискам.

История с сервера добавляется в чат. `chat_history_test.cpp` проверяет
перекрывающиеся страницы, пустой ответ, вставку между прежней историей и
новым сообщением, части длинного сообщения с общим ID, сохранение cookies,
квитанций и обновление media token. Идентификаторы моста непрозрачные;
они используются для совпадений, а не для лексикографической сортировки.
`java_ui_probe.cpp` проверяет запрос/продолжение из меню чата, один запрос
на чат, очередь после preload, позицию чтения, фоновый ответ, конец истории,
ошибку/повтор и сохранение загруженного RAM-хвоста после переподключения.
Сохранение до 200 записей ограничивает память. Обсуждение остаётся отдельным
списком своего потока; отдельного пункта локального архива нет.

Медиа имеют прямые команды в меню чата. Выбор файла и готовый результат
камеры сразу запускают передачу: отдельные «Прикрепить», проверка получателя,
предпросмотр и подтверждение перед отправкой удалены. Голосовой экран ждёт
первого **выбор / 5**, повторное нажатие останавливает и отправляет запись.
Для фото и кружка используется штатный видоискатель Motorola; адаптер
переводит **5** в его действие съёмки, второе нажатие останавливает кружок,
а сохранённый результат передаётся без ручной команды «Вставка».
Завершение определяется настоящим переходом камеры к готовому результату,
а не размером растущего файла.

Файловый выбор начинается с **Root**, показывает реальные корни, папки
и **../**. «Отправить фото/видео» определяет вид по расширению; остальные
файлы идут документами. Пользовательский оригинал сохраняется при отмене.
Временная запись удаляется после ACK или явной отмены; ошибка и обрыв
оставляют её для повтора. Документ при получении сразу сохраняется в
доступный `tmm/` с защитой от перезаписи, затем показываются путь и размер.
Полученное в фоне медиа открывается после возврата и разблокировки,
воспроизведение в скрытом окне не начинается.

Видео имеет меню **Смотреть / Смотреть в браузере**. Встроенное видео
использует всю область между системными полосами: **5 / 0 / Назад** —
закрыть, **3 / Дальше** — следующий фрагмент. Голосовое показывает состояние,
время и полосу; **выбор / 5** — пауза/продолжение/повтор, **влево / 4** —
сначала, **0 / Назад** — закрыть. Аватар и полученное фото используют один
просмотрщик; поворот и масштаб сохранены по отдельному запросу пользователя.

## Отключение локальной истории и время

В `tests/storage_test.cpp` проверены отключение чтения, сохранения сообщений
и квитанций, очистка управляемых архивов, включая прежние учётки, перезапуск хранилища и
включение записи снова. Очистка сохраняет черновики и пользовательские
файлы, пропускает неизвестные каталоги и символические ссылки.

`tests/java_ui_probe.cpp` проверяет Save/Back нового флажка, сохранение
выбора, переписку и квитанции в RAM, пустой чат после повторной загрузки
аккаунта, запрос одной записи, отсутствие повторных запросов, открытие
до подключения, поздний ответ после нового сообщения, повтор после ошибки
и отсутствие непрочитанного при фоновом завершении. Проверены точное
отображение готового `[дд.мм чч:мм] Автор: текст` и обычное время с часовым
поясом для живого сообщения. `tests/test_network.py` проверяет запрос одной
записи через настоящий OSCAR/TMM в трёх режимах подключения.

## Одна учётка, оповещения и исправления протокола

В `ui_settings_test.cpp` проверен перенос текущих глобальных UIN/пароля,
сохранение намеренно пустого пароля, выбор активной старой записи, когда
глобальных полей ещё нет, удаление всех `account.*` (в том числе лишних
слотов), `accounts` и `account_index`, а также повторный запуск миграции.
`java_ui_probe.cpp` проверяет единственную пару полей, **Назад / Сохр.**,
отмену черновика и сохранение с повторным чтением файла. Настоящий движок
ввода Motorola прошёл 17 проверок пароля в этой форме.

В `ui_probe.cpp` и `ui_paint_probe.cpp` проверены реальные отрисовки конверта
Java у свёрнутой группы и раскрытого чата, счётчик тихой доставки и сброс
непрочитанного после открытия чата, разблокировки, возврата из фона и меню.
Вызовы API оповещений наблюдаются через linker wrapper: обычная/закрытая
крышка/PIN, выбранные файл/громкость/вибрация, первые 60 секунд, повторный
сигнал и все три способа тихой доставки. `notification_audio_test.cpp`
запускает настоящий `Platform` из сборки с Qt прошивки и наблюдает передачу
файла и уровня в audio-only плеер, подавление «Нет»/нуля и создание,
повторное использование и удаление WAV из трёх нот. Этот тест не воспроизводит звук на динамике;
воспроизведение и громкость нужно подтвердить на телефоне.

`test_network.py` проверяет одиночный уход контакта в офлайн и пакет двух
таких записей, затем онлайн, сообщение и следующие запросы в том же
поколении соединения, в MD5/plain, MD5/TMME и XOR. Четыре байта предупреждения
и счётчика TLV теперь потребляются и в `03/0C`; они больше не разбираются
как пустой UIN. `test_wire.py` проверяет корректную и обрезанную запись под
ASan/UBSan вместе с 40 000 повреждённых пакетов.

У видео-only диалога камеры (`CreateCameraDlg` mode 2) остановка ведёт
через frame 4 / `CAM_UI_VideoPreviewView`: это проверено по коду прошивки
(`0x42e4bf5c`, `0x42e13e00`). Обработчик завершает этот путь так же, как
`VideoInsertView`, после возврата из native Show/stop стека. В
`camera_ui_v8_test.cpp` проверены реальная метаинформация PreviewView,
Fire/5 → stop → preview → Accepted, правая «Останов.» вместо отмены,
её отпускание и автоповтор после смены состояния, отмена до записи,
отложенное завершение, границы текущего
диалога и отмена. Это проверка Qt/ABI с видоискателем и результатом-фикстурой,
аппаратная съёмка не эмулируется. `media_workflow_probe.cpp` отдельно проверяет,
что готовый файл камеры запускает `UploadVideo`, а удаляется только после ACK.

Эти проверки не заменяют испытание физического микрофона и камеры.
Отчёты Qt/QWS находятся в `build/qws-startup-study/` и не входят в релиз.

## Постоянный системный значок

В **Интерфейс → Значок запущенного приложения** есть верхняя строка,
экран ожидания и выключение. По умолчанию выбрана верхняя строка; Save/Back
работают в том же черновике. `StatusIconV8` регистрирует группы ресурсов через
`ZHeader::registerInfo/changeStatus/unregisterInfo`: IM для верхней строки,
ICQ для экрана ожидания. Переключение сначала очищает предыдущий слот.

Это проверено по реальным `AreaList` и `findLocation` этой прошивки:
`MAINDISPLAY_HEADER_AREA` содержит 6 групп, `CLI_HEADER_AREA` — 4,
`MAINDISPLAY_IDL_AREA` — 10 и `CLI_IDL_AREA` — 7. ICQ отсутствует в обеих
верхних полосах, но присутствует в idle-группах. На внутреннем экране IM,
Bluetooth и USB входят в одну группу: ограничение отражено в списке выбора.
Клиент не меняет таблицы, файлы и ресурсы прошивки и не вводит новые индексы.

Объект регистрации живёт в `main` после захвата единственного экземпляра
до обычного выхода, настройки применяет через `Window::applySettings`.
Сворачивание и сохранение неизменного режима не создают повторных запросов.
Сетевые состояния и выбор статуса меняют только state уже зарегистрированного
значка: online/free/home/work — ICQ, away/NA/lunch/depression — away,
busy/DND/angry — busy, обе невидимости — invisible. Disconnected, Connecting
и Reconnecting используют серый штатный offline. Серой ICQ-ромашки нет. Размеры структур API — 16 и 20 байт. В клиенте остаются
несколько скалярных полей; временные строки освобождаются после сериализации.
Нет опроса или таймера. Готовые ICQ-ресурсы имеют 20×20 внутри и 40×20 снаружи.

`status_icon_test.cpp` запускает настоящий `ZHeader` и Qt/QCop в изолированной
прошивке. Endpoint `headerregister` наблюдает реальные пакеты `register()`,
`appStatusChanged(int)` и `unregister()`, включая ID слота, значение,
приоритет и четыре имени ресурсов. Проверены реальные таблицы размещения
и изображения всех пяти состояний, все 13 статусов и офлайн,
сохранение при hide/show окна, смена IM → ICQ → Нет,
отсутствие повторных запросов, очистка после выхода из главного цикла,
flush QWS, деструктор и отсутствие сервиса без падения приложения.
`java_ui_probe.cpp` проверяет три пункта, Save/Back, сохранение после перезапуска
и передачу правильного raw status при подключении, выборе статуса и обрыве;
`ui_settings_test.cpp` — значения и значение по умолчанию.

Это не запуск телефонного `ZHeaderServer`: отображение в системной полосе
и внешний экран ещё нужно подтвердить на V8. После аварийного завершения,
не выполняющего деструкторы, штатная регистрация может оставаться до следующего
запуска/обычного выхода native с тем же режимом или перезапуска телефона.

Проверка ресурса файла через настоящий `RES_ICON_Reader` показала, что
имя PNG приложения не принимается: панель читает ID системной темы.
Имена в shared memory ограничены 60 байтами, слоты — фиксированными
таблицами. Поэтому числовой badge рядом с ICQ не реализован в рамках
изменений только клиента. Счётчики клиента и внешний текст уведомлений
сохраняются. Прошивка и панель не модифицируются.

## Исправления записи и аудио

Код ошибки 7 в таблице `MediaPlayerEngine::getErrorDescription` этой прошивки
соответствует `AUDIO_DEVICE_IS_BUSY`, а не повреждённому MP3. Оповещения
используют парные `MP_CreateRingtone/MP_DeleteRingtone`, подавляют повторный
запуск, пока сигнал активен, и не конкурируют с записью или просмотром.
Перед медиа текущий сигнал останавливается. Ошибка освобождает устройство,
следующая попытка не блокируется навсегда. `notification_audio_test.cpp`
наблюдает настоящую политику Platform, `media_lifecycle_test.cpp` —
метаданные, отложенные события, очистку и восстановление состояния.
Динамик и звуковой сервис на телефоне требуют отдельного испытания.

Камера проверяет активный CAM_UI_Frame и его view, даже когда view не
является дочерним окном CAM_UI_Dlg. `camera_ui_v8_test.cpp` проверяет этот
путь, Show до публикации active frame, Fire/5/правую Останов., завершение
PreviewView и запрет превращать отмену в отправку. Файл сохраняется в
принадлежащую клиенту staging-копию до DestroyCameraDlg, после него
атомарно переименовывается. Поздний уход в фон после Accepted не отменяет
результат. Невозможность сохранить принятый результат показывает ошибку.

При остановке голосового UI сразу переходит к «Сохраняю запись...».
После ожидания доступности устройства worker повторно проверяет Stop,
а не начинает новое чтение. Только worker управляет микрофоном:
межпоточный pause/close не используется, поскольку AAL_read и pause
берут один нативный mutex. Проверка с управляемым источником останавливает
запись после шести секунд и во время canRead, проверяет сигналы, AMR,
отмену и повтор. Зависание физического аудиосервиса в QEMU не воспроизводится.

Просмотрщик фото больше не рисует подсказку поверх изображения.
`media_workflow_probe.cpp` проверяет всегда доступный `/`, путь вне mystuff,
JPEG/GIF/BMP и сохранность выбранных файлов после ACK/отмены.

## Существенные ограничения

* Нативный клиент выбирает APN/профиль Интернета сам: в Java это делает VM.
  Сеть всегда работает в рабочем потоке, переключателя «Асинхронная
  передача» в интерфейсе нет.
* Мост не сообщает программу собеседника; пункт «Инфо о клиенте» показывает
  это ограничение. Корни файловой системы имеют реальные имена MotoMAGX,
  отличающиеся от псевдонимов Java JSR-75.
* Поворот/масштаб фото и показ/скрытие пароля оставлены по прежним запросам.
  Удаляются только устаревшие настройки схем, фона и дополнительных учёток;
  остальные данные и скрытые технические параметры сохраняются.
* API камеры и плеера привязаны к ABI прошивки SAedition 1BR. Неизвестный
  ABI нельзя считать совместимым по одному совпадению имени библиотеки.
  Параметры, возврат `QString` и переходы диалога проверяются отдельно
  от физической съёмки и воспроизведения.
* Полный клиент с сетевыми потоками не работает в используемом QEMU
  linux-user: старая LinuxThreads вызывает неподдерживаемый `clone`.
  Поэтому сеть испытывается с настоящими потоками хоста, ARM — отдельно
  для UI/ABI, данных и криптографии. Управляемый планировщик в тесте записи
  не доказывает работу LinuxThreads под эмулятором.
* Реальная скорость, расход батареи и пиковая память на V8 не измерены.
  Картинки проверяются до декодирования, файлы передаются порциями на диск;
  это свойства реализации, а не измеренная экономия. Непрочитанные чаты
  сохраняются в памяти и не вытесняются как прочитанные.

## Требования к сборке и вводу

GCC 3.4.3 MontaVista с `-Os` неверно компилирует некоторые сравнения
индекса с пустым `std::vector`. Нужен `-fno-expensive-optimizations`;
`toolchain-vector-test` проверяет такие структуры на ARM. Старый линковщик
с `--gc-sections` удаляет используемые `.ARM.exidx/.ARM.extab`, и исключение
транспорта приводит к `terminate` вместо обработчика. Флаг отключён,
`exception-test` проверяет исключение через настоящие объектные файлы.
Изменение этих флагов требует полной пересборки.

Редактор использует штатный `KbUIController`, создаваемый до
`ZMultiLineEdit`, и события `ZIMIndicatorChangeEvent`. Перед сменой поля
старый режим завершается, затем активируется новый. Тип пароля — штатный
`FIELD_TYPE_PASSWORD`, без словаря и авторегистра; введённые буквы и пробелы
не нормализуются. Авторизация использует Latin-1, PSK — UTF-8.
Штатная библиотека может скрывать подпись системного языка; Input Cycle
показывает её. Клиент не устанавливает мод и не меняет конфигурацию языков.
Тестовая загрузка `.km` обходит ограничение перечисления файлов под QEMU
и в клиент не включается.

Launcher отбрасывает stdout Motorola, содержащий вводимый текст, и сохраняет
stderr. `collect-log.lin` собирает текущий и предыдущий журналы без настроек
и истории. Старые журналы 0.1.1 могли содержать ввод; их содержимое требует
проверки перед пересылкой. Показанный пароль снова скрывается при фоне,
закрытии крышки и блокировке; PIN защищает интерфейс, не файлы на диске.

## Кэш и заставки Native 0.1.13

`media-cache-test` запускается на host и ARM: лимиты числа/объёма файлов,

Для видео проверяются кэш готового файла и отдельный запрос следующего
фрагмента с тем же профилем; физическое воспроизведение остаётся аппаратным
тестом. Отмена и смена учётной записи очищают соответствующее состояние.

`ui-probe` проверяет все 13 ромашек в настоящих ZListBoxItem, значок текущего
статуса в главном меню, PIN со стиранием/ошибкой/сворачиванием, вариант без
PIN и скрытие контакт-листа заставкой подключения. Сцены `status-menu`,
`pin`, `pin-error`, `lock`, `connection` позволяют снять отдельные экраны;
градиент прогресса и заставка рисуются в общий буфер кадра. Значок TeleMotoMax
входит в пакет и fingerprint. Время на заставке обновляется раз в минуту.
Служебная ссылка видео скрывается только при отображении: исходный текст
и меню браузера сохраняются. Host-тест проверяет подпись, длительность и
обычные ссылки в подписи.

## Проверка на телефоне

1. Установить PEP отдельным пунктом и настроить аккаунт и сеть. Проверить
   ввод и индикаторы Motorola, **Назад** без сохранения, **Сохр.**, перенос
   текущих UIN/пароля со старой версии, повторный запуск и сохранность данных.
   Выбора/добавления/удаления учёток в native нет. Java остаётся отдельно.
2. Сверить главное меню, контакты и контекстное меню чата с Java V8 1.31.
   Проверить выбранный ответ, софт-клавиши, приватные списки, шаблоны,
   свёрнутые группы и онлайн/всего без контактов недоступной сети.
3. Подключиться обычным потоком и с TMME/1. Проверить этапы/отмену,
   DNS при запуске, переподключение, квитанции и тихую доставку: значок
   непрочитанного есть, звука, вибрации и пробуждения нет.
4. Получить историю прямо в чате, запросить **Ещё с сервера**, проверить
   порядок, отсутствие повторов и стабильную позицию чтения при новом
   сообщении. Повторить после ошибки и переподключения; проверить вложения,
   обсуждение, новые чаты и цитирование с медиа между сетями.
5. Открыть фото/аватар, голосовое, оба пункта видео и следующий фрагмент.
   Проверить масштаб/поворот, паузу/повтор/перемотку голосового сначала,
   автоматическое сохранение документа и совпавшие имена файлов.
6. Открыть **Root** обеими командами отправки: файл должен уходить сразу,
   выбранный оригинал — оставаться. Снять фото; записать кружок и голосовое
   первым/вторым **выбор / 5** и правой **Останов.** без «Вставки».
   Остановить голосовое после шести секунд, нажать Назад во время остановки,
   повторить запись/кружок при входящем сообщении. Проверить ACK и журнал:
   `Voice recording` / `Camera video` показывают стадии без текста переписки.
   Фото искать и вне mystuff через `/`.
7. Загрузить вложение в фоне и вернуть приложение; оно должно открыться
   после открытия крышки и разблокировки. Проверить таймер блокировки,
   PIN и вариант без PIN, повторный запуск после сворачивания, громкость/
   вибрацию двух режимов, тишину первые 60 секунд и сигнал разрыва.
8. Проверить серый системный значок без сети, выбранные статусы, фон,
   два размещения, выключение значка и обычный выход. Проверить размеры
   интерфейса/чата, светлую/тёмную тему телефона и отсутствие наложенной
   подсказки на фото. Проверить внешний экран и отсутствие текста при PIN. Для аппаратного
   сбоя сохранить журнал и точную последовательность действий. Работа
   камеры, микрофона, декодера, связи, звука, крышки и внешнего экрана
   окончательно подтверждается только этим испытанием на V8.

## Заставка Native 0.1.14

Полоса подключения имеет фиксированную высоту одной строки при всех
этапах: короткие подписи, многоточие для длинного текста, без переносов.
`ui-probe` проверяет границу окрашенной полосы для длинных этапов, с длинной
произвольной строкой и явным переносом, для RU/EN и шрифтов 16/24.
Сцены `connection` и `connection-large` проверяют вид на экране V8.
Значок 96×96 строится из существующего рисунка TeleMotoMax в
`telemotomax/util/icon/make_icon.py`; `native-v8/tools/make_logo.py`
воспроизводит PNG. В пакет входит `native-v8/resources/logo.png`.

## Ручное отключение Native 0.1.15

Меню «Отключиться» сбрасывает присутствие контактов синхронно. Ответ
остановленного worker имеет прежнее поколение и отбрасывается, поэтому
ожидать от него сброса статусов было неверно. Возврат из меню в контакт-лист
пересобирает строки, порядок, фильтр офлайн и групповые счётчики.
`ui-probe` нажимает настоящий пункт главного меню с двумя онлайн-контактами,
проверяет оба статуса offline до нового события, возврат через Back,
настоящую иконку offline и скрытие прочитанных офлайн-контактов. Непрочитанные
сообщения и их видимость сохраняются.
