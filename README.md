# Мост ICQ (OSCAR) → Telegram

Сервер, который говорит по протоколу ICQ (OSCAR) и притворяется ICQ-сервером.
Клиент подключается к нему по UIN и паролю, а с той стороны моста работает ваш
аккаунт Telegram.

Подойти должен любой клиент, работающий по OSCAR, — в нём достаточно указать
свой адрес сервера вместо `login.icq.com`. Проверялось на Motorola V3 со
сборками Jimm `0.6.091219-jimm-MOTOROLA-light`, `0.7.100123-jimm-MOTOROLA-light`
и Jimm 0.5.1; часть решений подогнана именно под особенности Jimm — они
отмечены в тексте и в комментариях к коду.

* Каждый чат Telegram — отдельный контакт с собственным UIN.
* Рядом может жить второй аккаунт — MAX (max.ru): его чаты приходят отдельной
  группой, всё остальное общее.
* Группы контактов — папки Telegram (или типы чатов, если папок нет).
* Вложения приходят текстовой пометкой: `[фото] подпись`, `[голосовое 0:14]`,
  `[файл отчёт.pdf, 2.0 МБ]`.
* Пока телефон не в сети, сообщения копятся в базе и досылаются при следующем
  входе — включая то, что пришло, пока мост был выключен.

## Что нужно

* Сервер с Python 3.11+ и белым IP (или проброшенным портом).
* Телефон или компьютер с ICQ-клиентом, умеющим протокол OSCAR и позволяющим
  указать свой адрес сервера. Годится любой доступ в интернет, включая GPRS.
* Ключи приложения Telegram — свои. Получите их на https://my.telegram.org →
  API development tools и впишите `api_id` и `api_hash` в `config.toml`;
  в `config.example.toml` они пустые нарочно. Чужие публично известные ключи
  (вроде `api_id = 2899` из telegram-cli) не годятся: Telegram гасит созданные
  с ними сессии через минуту после входа.

Заодно проверьте `device_model`, `system_version` и `app_version` — ими мост
представляется серверу Telegram; по умолчанию это обычный настольный клиент
под Linux.

Развёртывание на отдельной машине описано в [DEPLOY.md](DEPLOY.md),
разбор угроз и ограничений — в [SECURITY.md](SECURITY.md).

## Совместимость

Мост реализует ту часть OSCAR, которой пользуются клиенты ICQ: вход (XOR и
MD5), серверный контакт-лист, присутствие, обмен сообщениями по каналам 1 и 2,
уведомления о наборе, метазапросы с анкетой и поиском.

Проверено вживую:

| Клиент | Где |
|---|---|
| Jimm `0.6.091219-jimm-MOTOROLA-light` | Motorola V3 |
| Jimm `0.7.100123-jimm-MOTOROLA-light` | Motorola V3 |
| Jimm 0.5.1 | Motorola V3 |

Несколько решений продиктованы разбором исходников Jimm — например, порядок
частей контакт-листа, схема подсчёта MD5 при входе и признак «умею принимать
уведомления о наборе». Другие клиенты OSCAR должны работать, но не проверялись;
если ваш ведёт себя иначе, включите подробный журнал (`BRIDGE_LOGLEVEL=DEBUG`)
— в нём видно каждый кадр в обе стороны.

## Установка

```bash
git clone <этот каталог> /opt/icq-tg-bridge
cd /opt/icq-tg-bridge
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
cp config.example.toml config.toml
$EDITOR config.toml
```

Если в venv не оказалось pip (бывает на Ubuntu без пакета `python3-venv`):

```bash
curl -sS https://bootstrap.pypa.io/get-pip.py | .venv/bin/python
```

Заполните в `config.toml` как минимум:

```toml
[oscar]
uin = "1"                 # это вы будете вводить в Jimm
password = "своё"         # обязательно поменяйте changeme
bos_host = "example.org"  # адрес сервера, видимый с телефона
```

Пароль набирается на телефонной клавиатуре, так что удобнее короткий цифровой —
но он же защищает открытый в интернет порт, так что не берите `1234`.

Один раз авторизуйтесь в Telegram (спросит телефон, код и, если включён,
облачный пароль):

```bash
./run.py login
```

Запуск:

```bash
./run.py
```

`run.py` сам находит `.venv` рядом с собой, так что отдельно активировать
окружение не нужно.

Как служба:

```bash
sudo cp icq-tg-bridge.service /etc/systemd/system/
sudo systemctl enable --now icq-tg-bridge
```

## Настройка Jimm на телефоне

В Jimm 0.7.0: *Опции → Аккаунт* — введите UIN и пароль из секции `[oscar]`.
В *Опции → Сеть* (в некоторых сборках — *Соединение*) укажите адрес сервера
и порт вместо `login.icq.com:5190`.

Если оператор режет нестандартные порты, поставьте в `config.toml`
`port = 443` и укажите тот же порт в Jimm — трафик пойдёт как обычный HTTPS
по номеру порта (шифрования при этом нет, см. ниже).

## Как это выглядит в работе

Контакт-лист приходит с сервера при входе: группы — ваши папки Telegram,
контакты — чаты, подписанные названиями чатов. Все контакты показаны в сети.

Эмодзи переводятся в коды смайлов Jimm — клиент подставляет вместо них свои
картинки. 132 эмодзи разложены по всем 32 смайлам стандартного набора:
`😀` → `:-D`, `👍` → `(y)`, `❤️` → `*IN_LOVE*`, `🌹` → `@}->--`, `🤒` → `:-!`,
`😈` → `]:->`, `🍺` → `*BEER*`. Тем, чему картинки не нашлось, достаётся
словесная пометка (`🔥` → `*огонь*`), флагам — код страны (`🇷🇺` → `[RU]`),
редким — имя символа (`🫠` → `[melting face]`).

Коды отделяются пробелами, как это делает сам Jimm при вставке смайла из меню,
повторы схлопываются (`😂😂😂` → `:-D`), модификаторы тона кожи и склейки
составных эмодзи убираются. В итоге на телефон не уходит ни одного символа вне
базовой плоскости Юникода — иначе старый экран рисует квадраты. Отключается параметром
`emoji_to_text`.

Обратный перевод включён тоже (`text_to_emoji`): смайл, отправленный с телефона,
приходит собеседнику эмодзи, а не строкой `*IN_LOVE*`. Словесные коды набора
(`lol`, `wow`, `rofl`) намеренно не переводятся, иначе обычные слова в тексте
превращались бы в картинки. Время `8:00`, счёт `8-1` и пути `C:/temp` не трогаются.

Статусы контактов отражают Telegram: собеседник в сети — контакт в сети,
был недавно (или отошёл меньше 15 минут назад) — «отошёл», остальное —
не в сети. Смена статуса прилетает на телефон сразу. У групп, каналов и
ботов статуса нет, они всегда показаны в сети.

Галочка у отправленного с телефона сообщения появляется, когда собеседник
**прочитал** его в Telegram, — мост придерживает подтверждение до отметки о
прочтении. Если хочется старого поведения (галочка сразу после отправки),
поставьте `ack_on = "sent"`. Если галочек не видно вовсе, включите в Jimm
опцию информации о доставке: клиент показывает их только при ней.

Работает и «печатает»: когда собеседник набирает сообщение в Telegram, это
видно на телефоне, а когда вы набираете в Jimm — видно собеседнику. Клиент
показывает уведомление, только если оно включено в его настройках.

Чтобы Jimm вообще стал присылать «печатает», мост объявляет каждому контакту
возможность `CAP_TYPING` в сведениях о пользователе: клиент проверяет её
перед отправкой уведомления и без неё молчит.

Гасит индикатор сам мост: Jimm этого не делает — в его коде сброс есть только
на уход контакта в офлайн, так что без нашей помощи надпись висела бы вечно.
Telegram повторяет уведомление каждые несколько секунд, поэтому индикатор
снимается после восьми секунд тишины, а также сразу — когда пришло сообщение
или собеседник отменил набор.

Входящее сообщение из группы или канала приходит с именем автора:
`Вася: ну что, поехали`. Для личных чатов имя не дублируется.
Длинные сообщения режутся на куски по 900 символов — параметр
`max_message_chars`.

Ответ с телефона уходит в тот чат, чей UIN открыт.

Чат, которого не было в списке на момент входа (например, вам написал
кто-то новый), сразу получает UIN, и его сообщения доходят до телефона.
В контакт-листе он появится после перезахода в Jimm — контакт-лист
отдаётся целиком при входе, а серверные правки списка клиент не принимает
(из семейства 0x13 он разбирает только запросы авторизации).

По той же причине удалённый чат пропадает из Jimm не сразу. Мост замечает
пропажу при обновлении списка — раз в десять минут — и тогда помечает контакт
не в сети; из контакт-листа он исчезнет при следующем входе. Запись в базе
сохраняется: если чат вернётся, за ним останется прежний UIN, а с ним и
история переписки на телефоне.

## Что происходит, когда телефон не в сети

Сообщение уходит в очередь в SQLite и досылается при следующем входе.
Хранится не больше `offline_queue_per_chat` записей на чат.

Накопленное уезжает так, как это задумано в ICQ, — офлайн-сообщениями: при
входе клиент сам их спрашивает, мост отдаёт пачку с настоящим временем каждого
сообщения, и Jimm показывает его сам, без нашей приписки. Записи остаются в
очереди, пока клиент не подтвердит приём всей пачки (`0x003E`); не подтвердил —
уйдут заново обычным потоком. Клиент, который офлайн-сообщений не спрашивает,
получает то же самое обычным потоком через пару секунд после входа.

Фильтр по статусу действует и на пачку: что при текущем статусе доставлять
нельзя, в неё не попадёт — придержится или выбросится, как и в обычном потоке.

То, что залежалось уже в сеансе (например, пока телефон был в «занят»),
приходит обычным сообщением с меткой времени: `[06.09 18:42] Вася: привет`.

Через очередь идут вообще все сообщения, не только накопленные: приём из
Telegram только пишет запись в базу и будит отправителя, а тот выгребает её
отдельной задачей. Так медленный GPRS не задерживает приём новых сообщений.
Метку времени в тексте получает лишь то, что пролежало в очереди больше минуты
и ушло обычным потоком, — у офлайн-сообщений время своё.

Запись удаляется только после того, как телефон подтвердил получение.
Сообщения уходят расширенным форматом ICQ (канал 2), на который Jimm отвечает
`SNAC 04/0B` — это настоящее подтверждение от клиента, а не факт записи в сокет.
Если подтверждения на первое же сообщение не будет (`ack_timeout`, 30 секунд),
мост перейдёт на обычные сообщения канала 1 и повторит отправку, чтобы ничего
не потерялось. Но молчание — не доказательство: зависший или отвалившийся без
закрытия соединения телефон тоже ничего не подтверждает, а обычные сообщения
ушли бы в никуда и пропали из очереди. Поэтому решение «подтверждений не будет»
принимается только если клиент после отправки подавал признаки жизни — пинг,
набор текста, что угодно; совсем немой сеанс мост закрывает сам по
`idle_timeout`, и очередь дождётся следующего входа. Проверка повторяется для
каждого сеанса. Режим отключается параметром `delivery_ack`.

На GPRS оборванное соединение может оставаться открытым на стороне сервера,
и тогда сообщения уходили бы в никуда. Jimm шлёт keepalive каждые две минуты,
так что мост считает телефон отключившимся после `idle_timeout` секунд тишины
(по умолчанию 360) и переводит сообщения в очередь. Отсчёт включается, только
если keepalive от клиента хоть раз приходил, — если вы отключили их в Jimm,
сессия рваться по таймауту не будет.

Пока мост не запущен, событий из Telegram он не получает. Поэтому при старте
`catch_up` догружает пропущенное: берёт чаты с непрочитанным и вычитывает
сообщения новее последнего доставленного на телефон. Отметка ведётся по каждому
чату отдельно, так что одно и то же не приедет дважды.

## Папки, архив и свои сообщения

Группы контакт-листа — это папки Telegram, и раскладка повторяет его логику:
явно добавленный в папку чат остаётся в ней всегда, а попавший по типу
(«все каналы», «все группы») папка может исключить своими галочками
«кроме заглушённых», «кроме прочитанных», «кроме архивных» — мост их учитывает.
Чаты из архива, не попавшие ни в одну папку, собираются в группу
`archive_group`; пустое имя раскладывает их как обычные.

Когда `roster_limit` режет список, в него идут самые свежие чаты и все
избранные. Папки из `background_groups` — фоновые: их чаты претендуют на
место последними и попадают в список, только если после остальных осталось
место. Исключение — чат из такой папки, писавший телефону за последние
`background_hours` часов: он идёт наравне со всеми (в списке появится после
перезахода, как и любой новый). Сообщения из отложенных чатов приходят как
обычно, и найти их можно поиском.

Свои сообщения, написанные с других устройств, по умолчанию на телефон не
приходят. `mirror_outgoing = true` показывает их как «Я: …» — разговор на
телефоне становится двусторонним. Отправленное с самого телефона обратно не
возвращается: мост помнит номера своих сообщений.

## Вторая сеть: MAX

Помимо Telegram мост умеет держать аккаунт MAX (max.ru). Его чаты — личные,
группы и каналы — приходят на телефон одной группой `MAX` (название в
`group`), а дальше с ними всё как с Telegram: сообщения в обе стороны,
пометки вложений, отправитель в группах, «печатает» и статусы собеседников
(по событиям присутствия), отметка прочтения на телефоне, `!last`, `!render`
и `!lastfoto`, карточка контакта, поиск по названиям, избранное, `roster_limit`
и фоновые группы. Ограничение списка у MAX своё — `roster_limit` в секции
`[max]`; общий `roster_limit` из `[bridge]` касается только Telegram.

Чего нет: заглушить чат MAX с телефона нельзя (библиотека не умеет) —
попытка отвечает отказом; «печатает» с телефона в MAX не передаётся; папок
у MAX нет; поиск — только по своим чатам.

Включается в секции `[max]`: `enabled = true`, номер телефона в `phone`, вход
один раз командой `python3 run.py login max` — код придёт в SMS (в приложении
MAX). Сервер пускает с нового устройства только аккаунты с включённой
двухэтапной проверкой: без неё вход отвечает «Требуется установить 2FA» —
задайте пароль в приложении (Настройки → Безопасность) и повторите. Сессия хранится в `session` (по умолчанию `max.session`) и, как и
сессия Telegram, равносильна доступу к аккаунту.

Официального API для пользовательского аккаунта у MAX нет. Мост работает через
[maxapi-python](https://github.com/MaxApiTeam/PyMax) — библиотеку, говорящую с
сервером тем же протоколом, что и приложение. Её авторы предупреждают: протокол
может смениться без объявления, использование может нарушать условия сервиса,
аккаунт могут заблокировать. Телеметрию мост в MAX не отправляет.

## Контакт «Claude»

В контакт-листе может жить контакт `Claude` (в группе `Боты`): всё, что
ему пишете с телефона, уходит в Claude Code — программа `claude -p`
запускается под тем пользователем, от которого работает мост, по его
подписке и с его настройками. Ответ приходит от контакта; пока он
готовится, контакт «печатает», галочка на вашем сообщении ставится сразу.
Следующий вопрос продолжает тот же разговор (сеанс Claude Code хранится на
диске и переживает перезапуск моста), `!reset` начинает его заново,
`!help` напоминает про это.

Нужен установленный Claude Code (`emerge dev-util/claude-code` или
`npm install -g @anthropic-ai/claude-code`) и вход под пользователем моста:

```sh
su -s /bin/sh icqbridge -c 'claude -p "ответь одним словом: работает?"'
```

Включается в секции `[assistant]`: `enabled = true`. По умолчанию контакту
разрешены только сетевые инструменты (`tools = "WebSearch,WebFetch"`) — в
режиме печати спросить разрешения не у кого, всё неразрешённое просто
отклоняется. `""` — совсем без инструментов, `"default"` — весь набор, и
тогда разрешения берутся из `~/.claude/settings.json` того же пользователя.
Встроенная подсказка просит отвечать по-русски, коротко и без разметки под
маленький экран; своя дописывается в `system`, постоянные указания можно
положить в `CLAUDE.md` в рабочем каталоге `workdir`. Длинный ответ мост
режет на части как любое сообщение. Каждый вопрос — запуск отдельного
процесса, так что и простой ответ занимает секунд пять-десять.

Контакт не из Telegram: у него нет истории для `!last` и `!render`, карточка
своя, удалить его с телефона нельзя — только выключить в настройках.

## Статус в Jimm управляет доставкой

Статус, выставленный на телефоне, решает, что до него доезжает:

| Статус в Jimm | Что приходит | Что с остальным |
|---|---|---|
| Свободен для беседы | всё подряд, даже заглушённое | — |
| В сети, Отошёл | всё, кроме заглушённого в Telegram | не доставляется |
| Занят | личные и избранные, незаглушённые | придерживается |
| Не беспокоить | личные и избранные, незаглушённые | не доставляется |
| Недоступен | только избранное | не доставляется |
| Невидимый | только избранные собеседники | не доставляется |

Лестница получается ровная: чем тише статус, тем уже круг. «Занят» и «не
беспокоить» пропускают одно и то же и различаются лишь судьбой непрошедшего —
в «занят» оно ждёт, в «не беспокоить» пропадает.

Избранными считаются чаты, закреплённые в Telegram, плюс перечисленные по
названию в `favourites` в `config.toml`. Отметку можно поставить и с телефона:
команда `!fav` прямо в чате добавляет его в избранное или убирает оттуда.

Ручной выбор хранится отдельно от автоматического и сильнее его: обновление
списка диалогов перепишет признак закреплённого чата, но не решение, принятое
командой `!fav`. Так же можно снять избранность с закреплённого чата, если он
шумит.

Статус контакта в списке показывает не только присутствие, но и судьбу его
сообщений при вашем текущем статусе:

| Как выглядит контакт | Что это значит |
|---|---|
| его настоящий статус | сообщения дойдут |
| Не беспокоить | сообщения из этого чата не придут |
| Недоступен | сообщения копятся и приедут после смены статуса |
| Не в сети | собеседника нет; это важнее и не подменяется |

Так по контакт-листу сразу видно, кого сейчас не слышно. Настоящий статус
собеседника не теряется — он вернётся, как только чат снова начнёт проходить.

Про то, что важно, мост не гадает: он смотрит на уведомления в самом Telegram.
Заглушённый там чат молчит и на телефоне в любом статусе, кроме «свободен для
беседы», — держать второй список исключений не нужно, включая заглушённых
собеседников в личной переписке. Учитывается и отключение до определённого
времени, и беззвучный режим; истёкший мьют снова пропускает сообщения.

Исключение — два самых тихих статуса. В «недоступен» проходит только
избранное, в «невидимом» — только избранные собеседники: ни каналов, ни групп,
ни форумов, даже избранных. Зато проходят безусловно: пометку `!fav` ставят
руками и как раз ради таких случаев, поэтому мьют её не отменяет.

Невидимость клиенты шлют отдельным флагом, часто вместе с обычным статусом
(`INVISIBLE | AWAY`). Она самая тихая, поэтому и решает: если в связке есть
её флаг, режим будет по ней.

«Занят» — статус временный: групповые сообщения не пропадают, а ждут. Когда вы
его снимаете, приходит всё, что моложе `busy_hold_minutes` (по умолчанию 30);
что залежалось дольше — отбрасывается. Новый фильтр к придержанному не
применяется: эти сообщения отложены именно из-за «занят», и человек уже
вернулся. Исключений два: переход сразу в тихий статус («не беспокоить» или
«недоступен») — тогда придержанное не всплывает вовсе, и заглушённые в Telegram
чаты — их придержали как раз из-за мьюта, поэтому возврат в сеть его не
отменяет. Дойдут они только в «свободен для беседы», где проходит всё.

У «не беспокоить», «недоступен» и «невидимого» накопления нет вовсе: сообщение
остаётся в Telegram, и поднять его можно командой `!last` в нужном чате. Смысл
этих статусов в том, чтобы телефон молчал, а не откладывал пачку на потом.

Статусы вроде «Занят» клиенты нередко шлют в связке с другими битами
(`DND | OCCUPIED | AWAY`), поэтому режим определяется по флагам, а не по точному
совпадению кода.

## Аватарки

Клиент может показывать фотографию чата в списке контактов и в карточке. По
умолчанию это выключено — за картинками телефон ходит вторым соединением, и на
GPRS такой расход не всем нужен; включается `avatars = true` в `[bridge]`.
Работает это так: вместе со статусом контакта мост присылает примету картинки, а клиент,
увидев незнакомую, сам приходит за ней — отдельным соединением к службе
аватарок (семейство `0x10`, оно же BART). Мост отвечает на запрос адресом того
же сервера и одноразовым cookie, так что открывать ещё один порт не нужно.

Примета считается из идентификатора фотографии в Telegram: сменил человек фото —
сменилась примета, и телефон запросит новую. Картинка тянется из Telegram только
тогда, когда её действительно попросили, обрезается в квадрат `avatar_size` и
ужимается до `avatar_max_kb`; готовые лежат в памяти до смены фотографии.

Старые сборки Jimm берут из ответа только имя хоста и стучатся на порт 5190,
поэтому аватарки доедут, если мост слушает именно его. На другом порту всё
остальное работает по-прежнему — телефон просто не получит картинку.

Пока настройка выключена, мост не шлёт примет и отвечает на запрос службы
отказом — ровно как до появления этой возможности.

## Карточка контакта

«Информация» в Jimm показывает сведения о чате: название, тип (личный чат,
группа, канал, бот), `@имя`, число участников, описание, а в поле домашней
страницы — ссылку `t.me/…`. Для личных чатов подставляется телефон, «о себе»
и день рождения с возрастом, если они видны.

В разделе «Работа» карточка показывает пометки самого моста: поле «Должность»
содержит «Избранный» и «Заглушенный» — по одному слову на пометку, оба через
запятую, если верны обе. Пометок нет — поле пустое и не показывается вовсе, так
что достаточно взгляда, чтобы понять, дойдут ли сообщения из этого чата и
считается ли он важным.

Telegram разрешает указывать день рождения без года — такую дату клиент в своём
поле не покажет вовсе, поэтому она дописывается строкой в «о себе».
Учтите, что «о себе» и дата рождения видны далеко не у всех: это зависит от
настроек приватности собеседника и от того, заполнил ли он их вообще. Работает через метазапрос ICQ `0x04B2`, которым клиент спрашивал анкету
пользователя.

Ответ приходит шестью пакетами (основные сведения, дополнительные, работа,
заметки, интересы, конец) — иначе карточка не появится: клиент показывает её,
только собрав не меньше пяти частей.

## Поиск чатов

Окно поиска в Jimm (то, где искали людей по анкете) ищет по чатам Telegram:
введите название в поле «Ник» — мост сперва посмотрит среди уже известных
чатов, а если там пусто, поищет в самом Telegram. Найденный чат сразу получает
UIN, так что ему можно написать; в контакт-листе он появится после перезахода.

## Форумы

Супергруппа с темами (форум) — это несколько чатов в одном, и мост так их и
показывает: каждая тема становится отдельным контактом, а название форума —
группой контакт-листа.

```
Рабочий форум
   ├── Общее
   ├── Разработка
   └── Дежурство
```

Сообщение уходит именно в ту тему, из окна которой вы пишете. Тема, созданная
после входа, заводится на лету: её сообщения дойдут сразу, а в контакт-листе
она появится после перезахода. Сколько тем брать из форума — `topics_limit`
(по умолчанию 50).

## Про версию контакт-листа

При входе Jimm присылает версию своего списка (`13/05`), и напрашивается
ответить коротким «не менялся» (`13/0F`), сэкономив несколько килобайт.
Так делать нельзя: клиент засчитывает такой ответ внутренним флагом, но
переход к следующему шагу входа у него написан внутри разбора **полного**
списка. Получив `13/0F`, Jimm навсегда зависает на «checking roster».
Поэтому список всегда отдаётся целиком.

## Списки видимости — это уведомления Telegram

В меню контакта есть «В невид. список» и «В видим. список». Клиент отправляет
их на сервер как правки списков приватности, и мост использует это как
переключатель уведомлений:

| Пункт в клиенте | Что делает мост |
|---|---|
| В невид. список | выключает уведомления чата в Telegram |
| Отменить невид. список | включает их обратно |
| В видим. список | включает уведомления |
| Отменить видим. список | выключает их обратно |

Настоящей невидимости здесь нет — в Telegram нет такого понятия, — зато
получается удобная пара к статусу «не беспокоить»: заглушённый так чат в нём
молчит, а в контакт-листе показывается заглушённым. Список игнорируемых
работает как «в невид. список».

То же самое можно сделать и со стороны Telegram: мост читает настройки
уведомлений при обновлении списка чатов и сразу поправляет статус контакта на
телефоне — снятый на десктопе мьют доезжает сам, ждать смены своего статуса
не нужно.

А вот пометку `[i]` рядом с контактом клиент рисует по контакт-листу и правит
только при входе: сервер шлёт заглушённые чаты как элементы списка запрета, но
на лету такие правки клиент не слушает. Поэтому пометка догоняет Telegram при
следующем подключении телефона, тогда как статус и доставка меняются сразу.

## Удаление контактов

В клиенте есть два пункта, и мост понимает оба:

| Пункт в Jimm | Что происходит |
|---|---|
| Удалить | чат удаляется в Telegram: из групп и каналов мост выходит, в личной переписке удаляет историю у себя |
| Удалиться из его КЛ | то же, но переписка удаляется **у обеих сторон** |

Оба действия необратимы, поэтому каждое закрывается своей настройкой:
`allow_delete` и `allow_delete_revoke` (обе включены). Что именно удалено,
записывается в журнал.

Тему форума удалить нельзя — в Telegram такой операции нет. Мост в этом
случае отвечает сообщением и убирает тему с телефона: из контакт-листа она
уходит, сообщения из неё перестают приходить, а в Telegram остаётся как была.
Обновление списка тему не вернёт — для этого найдите её поиском, и она снова
появится в контакт-листе.

## Команды с телефона

Прямо в окне чата можно набрать:

| Команда | Что делает |
|---|---|
| `!last` | сообщения этого чата за сегодня, с полуночи |
| `!last 10` | десять последних сообщений |
| `!lastfoto` | ссылка на последнее фото чата |
| `!lastfoto 3` | три последних фото |
| `!render` | страница переписки за сегодня: фото, видео и голосовые |
| `!render 20` | то же по двадцати последним сообщениям |
| `!fav` | добавить чат в избранное или убрать оттуда |
| `!help` | короткая справка |

История приходит ответом от того же контакта, свои сообщения помечены как «Я»:

```
[12:34] Вася: ну что, поехали
[12:35] Я: ага, выхожу
```

Больше `history_limit` сообщений (по умолчанию 100) команда не выгрузит —
это предохранитель, чтобы случайное `!last` в чате с многолетней перепиской
не забило GPRS-канал. Если предел достигнут, об этом придёт отдельная строка.

Текст, начинающийся с `!`, но не совпавший ни с одной командой (`!!!`,
`!что-то`), уходит в чат как обычное сообщение.

## Фотографии

Картинку в окно Jimm не вставить, поэтому фото приходит ссылкой на мини-сервер
самого моста, а открывается браузером телефона:

```
котик на подоконнике
http://203.0.113.10:8080/p/k3mQ7bR.jpg (7 КБ)
```

По команде `!lastfoto` мост берёт из чата последние снимки, ужимает их под
экран телефона (по умолчанию 176×220, пропорции сохраняются) и складывает
у себя. Качество
подбирается так, чтобы файл влез в `max_kb` — по умолчанию 40 КБ, иначе GPRS
будет тянуть его слишком долго. Скачивается миниатюра из Telegram, а не
оригинал: на 176 точках разницы не видно, а трафика в разы меньше.

Снимки лежат в каталоге `photos` и удаляются через `keep_hours` (48 по
умолчанию). Ссылка содержит случайный токен, других маршрутов у сервера нет.
Но это обычный HTTP без пароля: кто знает ссылку — увидит картинку.

Порт (по умолчанию 8080) нужно пробросить так же, как 5190:

```bash
iptables -t nat -A PREROUTING -d 203.0.113.10/32 -p tcp -m tcp --dport 8080 \
         -j DNAT --to-destination 10.0.0.5:8080
iptables -I FORWARD -d 10.0.0.5/32 -p tcp -m tcp --dport 8080 -j ACCEPT
```

Всё это отключается `enabled = false` в секции `[photos]`.

## Страница переписки: `!render`

`!lastfoto` отдаёт снимки по одному, а `!render` собирает переписку целиком —
одной ссылкой на страницу для встроенного браузера телефона:

```
!render
Собираю 12 сообщений, вложений 4 — это займёт время…
http://203.0.113.10:8080/r/3
12 сообщений, 4 вложений, ссылка живёт 30 мин
```

Устроена команда как `!last`: без числа берёт сегодняшние сообщения, с числом —
столько последних, но не больше `messages` (20 по умолчанию).

На странице:

| Что в сообщении | Что на странице |
|---|---|
| текст | текст в пузыре |
| фото | картинка прямо в странице, ужатая под экран |
| видео, кружок, гифка | превью-картинка из Telegram, под ней ссылка «смотреть» на файл 3GP (176×144, H.263 или MPEG-4 + AMR) |
| голосовое, аудио | ссылка на файл AMR |

Вид сделан похожим на Telegram настолько, насколько его понимает браузер такого
телефона: синяя шапка с названием чата, чужие сообщения белым пузырём слева,
свои — зелёным справа, имя отправителя синим, время серым. Разметка — XHTML
Mobile Profile на таблицах, цвета продублированы атрибутами: чего браузер
не понял, то пропустит, и страница останется читаемой.

Видео и звук перекодирует `ffmpeg` — нужна сборка с `h263` и
`libopencore_amrnb`. Без него текст, фотографии и превью видео соберутся всё
равно, а вместо ссылок на ролики и голосовые останутся пометки. Длина
обрезается по `video_seconds` и `audio_seconds`, вложения тяжелее
`source_max_mb` мост даже не качает.

Профиль видео подобран под плеер RAZR V3: он декодирует H.263 Baseline
Level 10 и MPEG-4 Simple Profile Level 0, а это 176×144, не больше 15 кадров
в секунду и **не больше 64 кбит/с** — файл выше уровня плеер просто не откроет.
Кодек выбирается `video_codec` (`h263` или `mpeg4`): если ролики не
открываются с одним, попробуйте другой; `video_kbps` и `video_fps` поднимать
выше уровня не стоит. `moov` пишется в начало файла — старые плееры не ищут
его в конце.

Ссылки от `!render` и `!lastfoto` уходят URL-сообщениями ICQ: клиент печатает
ссылку отдельной строкой и помечает сообщение своим значком. Своих ссылок Jimm
всё равно не подчёркивает — открыть её можно пунктом «Открыть ссылку» в правом
меню на выделенном сообщении, поэтому ссылка дублируется и в тексте: пункт
появляется по разбору текста, а не по полю. Если телефон не подтверждает приём
и мост переходит на простой канал, придёт обычный текст — типов сообщений
там нет.

Длинная переписка режется на части по `page_max_kb` (6 по умолчанию) со
ссылками «назад / далее» внизу: браузер телефона и WAP-шлюз оператора
отвергают ответы больше своего предела — у Openwave на V3 это около 10 КБ, и
шлюз показывает вместо страницы «413». Части живут по адресам `/r/3`, `/r/3/2`,
`/r/3/3`; в списке страниц переписка одна строкой.

Адрес страницы задаётся форматом `path` в `[render]`: по умолчанию `/r/{n}` —
сквозной номер, который легко набрать на кнопках. Есть ещё `{chat}` (название
латиницей: `/dacha-2026/3`) и `{token}` (случайная строка, как было раньше).
Занятый адрес переходит новой странице, старая остаётся доступной по токену.
`index = true` включает список живых страниц по адресу `/r/` — с названиями,
временем и остатком срока.

Ссылка живёт `ttl_minutes` (30 по умолчанию): после этого ни страница, ни её
вложения не отдаются, а файлы удаляются при ближайшей уборке.

Короткий адрес легко угадать, поэтому у мини-сервера есть пароль —
`password` в `[photos]`, он закрывает и страницы, и снимки. Проверяется тремя
способами, чтобы старый браузер точно справился хотя бы с одним:

| Способ | Как выглядит |
|---|---|
| окно HTTP Basic | браузер сам спросит пароль, имя — любое |
| форма входа | на странице без пароля показывается форма; после входа ставится cookie на месяц |
| ключ в адресе | `http://…/r/3?key=пароль` — удобно набирать с телефона; cookie ставится и так, а если браузер cookie не хранит (Motorola V3 — не хранит), все ссылки на странице получают токен сеанса в начале пути (`/s/…/m/abc.3gp`), и дальше можно ходить по ним без пароля. Токен именно в начале: старый браузер определяет тип файла по концу адреса, и расширение должно оставаться последним |

Ссылки, которые мост сам шлёт телефону (`!render`, `!lastfoto`), при
включённом пароле несут токен сеанса (`http://…/s/<токен>/r/3`): открыл — и пароль вводить не
нужно, дальше страница проносит токен по своим ссылкам. Сам пароль в ссылку
не попадает — он ушёл бы открытым текстом по OSCAR и остался бы в истории
клиента. Отключается `link_session = false`.

Неверный пароль считается как неудачный вход: после `login_attempts` попыток
адрес блокируется на `login_ban_seconds`, отдельно от счётчика OSCAR.

## Загрузки

Тот же мини-сервер умеет раздавать произвольные файлы — раздел `[downloads]`.
Положите в `dir` файлы, и они появятся по адресу `/d/<имя>`, а `/d/` покажет
их список с размерами. Задумано под jad/jar: Jimm на телефон ставится ровно
так — открыть `http://…/d/jimm.jad` в браузере телефона, дальше установщик
сам скачает JAR по ссылке из JAD. Типы для jad, jar, картинок, мелодий и
видео телефон получит правильные; остальное уходит как `octet-stream`.

Отдаются только файлы из самого каталога: без подкаталогов, скрытых и
обходных путей. Раздел по умолчанию не закрыт паролем — установщик телефона
пароля спросить не умеет; `protected = true` закрывает и его.

Отключается `enabled = false` в секции `[render]`; работает только вместе
с включённой `[photos]` — раздаёт их один и тот же мини-сервер.

## Журнал

Четыре уровня, и у каждого своя роль:

| Уровень | Что в нём |
|---|---|
| `ERROR` | то, чего быть не должно: необработанные ошибки, сбои фоновых задач |
| `WARNING` | то, что мост пережил сам: отказ в авторизации, бан за перебор, зависший телефон, неподтверждённые сообщения, отсутствие ffmpeg |
| `INFO` | события без содержимого: кто и каким клиентом подключился, что ушло телефону и пришло от него (чат, размер, канал, число частей), что и почему отсеяно по статусу, команды, правки контакт-листа, офлайн-пачки, аватарки, карточки, а при закрытии сессии — причина, длительность и счётчики |
| `DEBUG` | каждый SNAC в обе стороны с именем (`04/06 ICBM_SEND, 123 байт`), сами тексты сообщений, подтверждения по cookie, статусы контактов, набор текста, события Telegram |

Тексты сообщений появляются только в `DEBUG` — на `INFO` журнал можно
показывать, не раскрывая переписку. Пример:

```
INFO    oscar    соединение с 91.78.159.171:62597 (занято 1 из 8)
INFO    oscar    вход по MD5, клиент 'Jimm 0.7.0'
INFO    oscar    контакт-лист отдан: 100 контактов, 10 групп, 31 заглушённых; 142 элементов в 2 частях
INFO    oscar    клиент готов: 91.78.159.171:24529, 'Jimm 0.7.0'
INFO    oscar    офлайн-пачка: 3 сообщений (3 записей очереди) — ждём 0x003E
INFO    bridge   из Telegram: «Мама» (1000001) → в очередь телефону, 34 симв.
INFO    oscar    телефону ← «Мама» (1000001): 34 симв., канал 2 — ждём подтверждения
INFO    oscar    телефон подтвердил получение: «Мама» (1000001), cookie 3f1a9c02
INFO    bridge   из Telegram: «Дача» (1000004) — не доставляю (заглушён в Telegram)
INFO    bridge   «Мама» печатает — показываю на телефоне
INFO    bridge   «Мама» перестал печатать — пришло сообщение
INFO    oscar    от телефона → «Мама» (1000001): 12 симв., канал 1, cookie 000003e9
INFO    oscar    сессия 91.78.159.171:24529 закрыта: молчание 366 с; длилась 42 мин, телефону 8 сообщений, от телефона 3
```

«телефону ←» — это отправка в сокет, не доставка. Доставку по каналу 2
подтверждает сам телефон — строка «телефон подтвердил получение»; по каналу 1
подтверждений в протоколе нет, там «ушло» и есть всё, что известно.

Строки об отсеянном («не доставляю», «придержано») в шумных заглушённых
каналах идут потоком — `filtered = false` в `[log]` опускает их до `DEBUG`.

Уровень и файл задаются в секции `[log]` (`level`, `telethon_level`, `file`
с ротацией по `file_max_mb` и `file_keep`). Переменные окружения
`BRIDGE_LOGLEVEL` и `BRIDGE_TELETHON_LOGLEVEL` сильнее настроек — под OpenRC
их выставляет `bridge_loglevel` в `/etc/conf.d/icq-tg-bridge`, **только если
там не пусто**; пустое значение (умолчание) отдаёт слово `config.toml`. Так
конфиг задаёт постоянный уровень, а conf.d — временное перекрытие без правки
конфига. Под службой журнал и так пишется в `/var/log/icq-tg-bridge.log`
(OpenRC) или journald (systemd), `file` в `[log]` там не нужен.

## Ограничения

* Отправлять фото и файлы с телефона некуда — только принимать ссылкой
  по `!lastfoto` и `!render`. Входящие вложения в ленте по-прежнему приходят пометками.
* Правки контакт-листа с телефона не сохраняются: список ведёт Telegram.
  Jimm покажет «принято», но при следующем входе список снова придёт
  из Telegram.
* Протокол OSCAR не шифруется — между телефоном и сервером всё идёт
  открытым текстом, а пароль передаётся тривиально обратимым XOR. Это плата
  за совместимость с клиентом 2005 года. Не используйте пароль, который
  где-то ещё что-то значит.

  Кто дозвонится до порта, ограничивается настройками: `allow_from` пускает
  только названные адреса и подсети, `max_connections` ограничивает число
  соединений, а после `login_attempts` неудачных попыток адрес блокируется
  на `login_ban_seconds`. Подробности — в [SECURITY.md](SECURITY.md).
* Сессия Telegram (`tg.session`) — это полный доступ к вашему аккаунту.
  Храните её как ключ от квартиры.

## Проверка без телефона

Тесты не требуют ни Telegram, ни телефона: они поднимают сервер на локальном
порту и разговаривают с ним эмулятором Jimm, который повторяет разбор
настоящего клиента — вплоть до проверок длин и порядка полей.

```bash
.venv/bin/python tests/test_flow.py            # полный диалог: вход, список, сообщения
.venv/bin/python tests/test_roster.py          # контакт-лист, в том числе большой
.venv/bin/python tests/test_forums.py          # темы форумов
.venv/bin/python tests/test_hold.py            # статусы, придержание, !fav
.venv/bin/python tests/test_policy.py          # какой статус что пропускает
.venv/bin/python tests/test_typing.py          # «печатает» и его снятие
.venv/bin/python tests/test_access.py          # перебор пароля, лимиты, пути
.venv/bin/python tests/test_photos.py          # перекодирование и раздача снимков
.venv/bin/python tests/test_emoji.py           # смайлы
.venv/bin/python tests/test_history.py         # разбор команд
.venv/bin/python tests/test_telegram_side.py   # вложения и папки
.venv/bin/python tests/test_avatars.py         # аватарки: примета, служба, картинка
.venv/bin/python tests/test_render.py          # страница переписки и перекодирование
.venv/bin/python tests/test_assistant.py       # контакт «Claude»
.venv/bin/python tests/test_max.py             # сторона MAX
```

Все разом:

```bash
for t in tests/test_*.py; do .venv/bin/python "$t" || echo "СБОЙ: $t"; done
```
